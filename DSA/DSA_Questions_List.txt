================================================================================
TOPGREP TECH - DSA PREPARATION ROADMAP FOR MERN DEVELOPERS (108 TOP QUESTIONS)
================================================================================

This topic-wise roadmap is structured to prepare you for JavaScript and fullstack 
MERN interviews by gradually building logic from absolute basics up to intermediate levels.
It contains 108 high-yield questions categorized into 7 core topics.

Each question contains:
- Required Algorithm/Pattern
- Reasoning (Why) explaining its practical application in web and MERN Stack development.

================================================================================
TOPIC 1: STRINGS (30 Questions)
================================================================================

[EASY LEVEL]

1. Reverse String
   - Pattern: Two Pointers / In-place swap
   - Why: Reversing characters from both ends inward requires O(1) extra space and reverses the string in-place.
   - File: DSA/strings/01-reverseString.js

2. Check Palindrome
   - Pattern: Two Pointers
   - Why: Moving pointers inward from both ends allows early exit as soon as a mismatch is found.
   - File: DSA/strings/02-checkPalindrome.js

3. Count Vowels
   - Pattern: Iteration / Character Set Matching
   - Why: Scanning the string against a set of vowels identifies occurrences in O(N) time.
   - File: DSA/strings/03-countVowels.js

4. Count Consonants
   - Pattern: Iteration / Filter
   - Why: Filters out vowels and special characters, scanning only alphabetic consonants in O(N) time.
   - File: DSA/strings/04-countConsonants.js

5. Character Frequency
   - Pattern: Hash Map / Frequency Array
   - Why: A Hash Map provides O(1) lookup and insertions, ideal for tracking character occurrences.
   - File: DSA/strings/05-charFrequency.js

6. Remove Duplicate Characters
   - Pattern: Hash Set / Filter
   - Why: A Set inherently holds unique values, filtering out duplicate entries in O(N) time.

7. Capitalize First Letter of Each Word
   - Pattern: String manipulation / Word Boundary scanning
   - Why: Iterating and uppercase-matching characters after space boundaries cleans input.

8. String Rotation Check
   - Pattern: Concatenation ((A + A).includes(B))
   - Why: If string B is a rotation of A, it must be a substring of A concatenated with itself.

9. First Repeating Character in a String
   - Pattern: Hash Set
   - Why: Checking elements while iterating allows immediate detection of the first duplicate.

10. First Non-Repeating Character in a String
    - Pattern: Hash Map (Two-pass tracking)
    - Why: First pass builds counts; second pass retrieves the first character with a frequency count of 1.

11. Remove All Spaces from a String
    - Pattern: Iteration filter / RegExp replace
    - Why: Cleans and matches characters by stripping whitespaces.

12. Check if String Contains Only Digits
    - Pattern: Char-code boundary scan / RegExp test
    - Why: Validates numerical inputs on forms/text fields.

13. Valid Anagram Check (Easy Version)
    - Pattern: Character counting in a single loop
    - Why: Verifies matching character lengths and counts in a simple hash map.

14. Check if String is Subsequence of Another
    - Pattern: Two Pointers
    - Why: Checks if characters of string A appear in string B in the same order, using two index pointers.

15. Count Occurrences of a Substring
    - Pattern: Sliding window / Index scan with indexOf
    - Why: Iteratively scans the main string to tally occurrences of a specific substring.

[MEDIUM LEVEL]

16. Longest Substring Without Repeating Characters
    - Pattern: Sliding Window (Set/Map)
    - Why: Dynamically slides the window to expand for valid substrings and shrinks from the left on duplicates.

17. Longest Palindromic Substring
    - Pattern: Expand Around Center
    - Why: Expanding outwards from 2N-1 potential centers checks palindromic bounds in O(N^2) time.

18. Valid Parentheses
    - Pattern: Stack
    - Why: Last-in, first-out (LIFO) order matches nested brackets (closing bracket must match last open bracket).

19. String Compression
    - Pattern: Two Pointers (Read & Write)
    - Why: In-place editing requires a read pointer to count matches and a write pointer to output the summary.

20. Group Anagrams
    - Pattern: Hash Map with Sorted String Keys
    - Why: Sorted representations of anagrams are identical, serving as grouping keys in a map.

21. Roman to Integer
    - Pattern: Left-to-Right scanning with Lookahead
    - Why: Sequential addition with lookahead handles subtractions (like IV = 5 - 1).

22. Integer to Roman
    - Pattern: Greedy subtraction with value map
    - Why: Maps Roman numbers in descending order, building strings by subtractive compilation.

23. Longest Common Prefix
    - Pattern: Vertical character scanning
    - Why: Compares indices across all elements, failing immediately upon first mismatch.

24. Reverse Words in a String
    - Pattern: Split & Reverse / Two Pointers
    - Why: Reversing word positions while cleaning spaces maintains linear complexity.

25. Isomorphic Strings
    - Pattern: Double Hash Mapping
    - Why: Maps characters in string A to B and vice versa, verifying a strict 1-to-1 character relation.

26. Validate IP Address
    - Pattern: Split blocks + numeric check / Regex
    - Why: Verifies proper syntax of network strings for APIs/databases.

27. String to Integer (atoi)
    - Pattern: Sign matching + numeric digit accumulator
    - Why: Implements parser logics for parsing numeric values from leading string data.

28. Minimum Window Substring
    - Pattern: Sliding Window (Two Pointers)
    - Why: Contracts left pointer dynamically when a valid window is found to discover minimum length.

29. Longest Repeating Character Replacement
    - Pattern: Sliding Window (Max Frequency Tracking)
    - Why: Tracks window size while checking if non-majority characters fit within the allowance (K).

30. Valid Palindrome II
    - Pattern: Two Pointers with 1-character deletion fallback
    - Why: Pointers move inwards; on mismatch, checks if skipping either character produces a valid palindrome.

TOPIC 2: ARRAYS (30 Questions)
================================================================================

[EASY LEVEL]

31. Reverse Array
    - Pattern: Two Pointers
    - Why: Swapping elements from ends inward reverses the array in-place in O(N) time.

32. Find Maximum & Minimum Element
    - Pattern: Linear Scan
    - Why: Iterating once while maintaining minimum and maximum bounds is optimal.

33. Second Largest Element
    - Pattern: Single Pass Tracking
    - Why: Keeps track of current largest and second largest values in O(N) time, avoiding O(N log N) sort.

34. Check if Array is Sorted
    - Pattern: Single Pass comparison
    - Why: Compares current element to next element to check non-decreasing order in O(N) time.

35. Remove Duplicates from Sorted Array
    - Pattern: Two Pointers (Read & Write)
    - Why: Since elements are sorted, duplicate values are adjacent and can be skipped.

36. Move Zeroes
    - Pattern: Two Pointers (Write Pointer)
    - Why: Write pointer shifts non-zero items leftwards in order, then fills trailing spots with zero.

37. Contains Duplicate
    - Pattern: Hash Set
    - Why: Instant O(1) set lookup reveals duplicates.

38. Intersection of Two Arrays
    - Pattern: Hash Set
    - Why: Hash Set lookups match items in O(N) time rather than nested checks in O(N^2).

39. Find Prime Numbers in an Array
    - Pattern: Linear scan + Prime check helper (sqrt boundary)
    - Why: Filters prime values out of raw number lists using optimized checks.

40. Separate Even and Odd Numbers in Array (Partitioning)
    - Pattern: Two Pointers (Left & Right boundary swap)
    - Why: Places even numbers at start and odd numbers at end in-place in O(N) time.

41. Find the Missing Number
    - Pattern: Math (Sum Formula) / XOR
    - Why: Summing array elements and comparing to index sums isolates the missing value in O(1) space.

42. Squares of a Sorted Array
    - Pattern: Two Pointers
    - Why: Since extreme negatives yield large squares, two pointers at opposite ends find items in descending order.

43. Find Pivot Index
    - Pattern: Prefix Sum (Left vs Right sum)
    - Why: Calculates running sum comparisons dynamically without recalculating subarray sums.

44. Monotonic Array Check
    - Pattern: Single Pass directional scan
    - Why: Verifies if array is entirely non-increasing or non-decreasing in O(N) time.

45. Merge Two Sorted Arrays
    - Pattern: Two Pointers
    - Why: Compares the smallest available items of both arrays to build a merged sorted list.

[MEDIUM LEVEL]

46. Two Sum
    - Pattern: Hash Map
    - Why: Storing visited numbers allows finding the target complement (target - current) in O(1) time.

47. Three Sum
    - Pattern: Sorting + Two Pointers
    - Why: Sorting groups values to avoid duplicates easily and lets two pointers seek outer bounds.

48. Maximum Subarray (Kadane's Algorithm)
    - Pattern: Dynamic Programming / Greedy
    - Why: Decides at each index whether to add value to running sum or start a new subarray.

49. Merge Intervals
    - Pattern: Sorting
    - Why: Sorting intervals by start times ensures overlapping segments are contiguous.

50. Rotate Array
    - Pattern: Reversal Trick / Auxiliary Space
    - Why: Reversing parts of the array in place handles shift rotations in O(N) time and O(1) space.

51. Sort Colors (Dutch National Flag)
    - Pattern: Three Pointers (Low, Mid, High)
    - Why: Low and High pointers act as placement anchors for 0s and 2s, sorting in a single pass.

52. Product of Array Except Self
    - Pattern: Prefix & Suffix Products
    - Why: Storing cumulative products left and right of an element computes total products in O(N) without division.

53. Majority Element
    - Pattern: Boyer-Moore Voting Algorithm
    - Why: Pairs of differing values are cancelled out, leaving the majority element in O(1) space.

54. Container With Most Water
    - Pattern: Two Pointers
    - Why: Moves inward from ends, updating pointers that point to smaller heights.

55. Subarray Sum Equals K
    - Pattern: Prefix Sum + Hash Map
    - Why: Counts target sum matches by searching prefix sum differences (prefix - k) in a map.

56. Maximum Product Subarray
    - Pattern: Dynamic Programming (Min-Max Tracking)
    - Why: Stores maximum and minimum values because negative multiplications flip minimums to maximums.

57. Find All Duplicates in Array
    - Pattern: In-Place Marking (Index Sign Swap)
    - Why: Negating values at corresponding indices marks them as visited using the original array space.

58. Search in Rotated Sorted Array
    - Pattern: Modified binary search pivot check
    - Why: Determines which half of the rotated array is sorted to target searches in O(log N).

59. Find Peak Element in Array
    - Pattern: Binary search binary halves comparison
    - Why: Navigates values looking for boundary peaks in O(log N) time.

60. Longest Subarray with Sum K
    - Pattern: Sliding Window (Two Pointers) / Hash Map prefix sum
    - Why: Dynamically contracts window leftward to isolate the longest array window summing to target.

TOPIC 3: SEARCHING & SORTING (10 Questions)
================================================================================

[EASY LEVEL]

61. Linear Search Implementation
    - Pattern: Index traversal scan
    - Why: Compares list elements sequentially to find index target.

62. Binary Search Implementation (Iterative & Recursive)
    - Pattern: Divide and conquer index divisions
    - Why: Halves searching array boundaries dynamically to search elements in O(log N) time.

63. Bubble Sort Implementation
    - Pattern: Swap adjacent elements in nested loops
    - Why: Foundational conceptual sorting showing loop execution. Time: O(N^2), Space: O(1).

64. Selection Sort Implementation
    - Pattern: Find minimum element and place at boundary
    - Why: Simple algorithm minimizing index swaps. Time: O(N^2), Space: O(1).

65. Insertion Sort Implementation
    - Pattern: Build sorted array incrementally
    - Why: Highly efficient for nearly sorted data arrays. Time: O(N^2), Space: O(1).

[MEDIUM LEVEL]

66. Merge Sort Implementation
    - Pattern: Divide and Conquer / Recursion
    - Why: Standard stable sorting algorithm with guaranteed O(N log N) time complexity. Extremely common in theoretical questions.

67. Quick Sort Implementation
    - Pattern: Divide and Conquer / Pivot partitioning
    - Why: Most efficient in-practice sorting algorithm (O(N log N) average) illustrating partitioning.

68. Sort Array of Objects (Custom Comparator)
    - Pattern: Array.prototype.sort() with comparison function ((a, b) => a.prop - b.prop)
    - Why: Basic MERN application. You receive an array of objects from the database/API and must sort it by date, name, or price dynamically before rendering.

69. Search in 2D Matrix
    - Pattern: Coordinate mapping binary search
    - Why: Flattens 2D matrices conceptually to execute O(log (M * N)) binary search lookups.

70. Find First and Last Position of Element in Sorted Array
    - Pattern: Double Binary Search bounds
    - Why: Finds target indices boundaries by scanning mid splits left and right in O(log N) time.

TOPIC 4: LINEAR DATA STRUCTURES - STACK & QUEUE (10 Questions)
================================================================================

[EASY LEVEL]

71. Implement Stack using Array
    - Pattern: Array encapsulation (push/pop)
    - Why: Explores Last-in, First-out (LIFO) memory structure by wrapping JS native methods.

72. Implement Queue using Array
    - Pattern: Array encapsulation (push/shift)
    - Why: Explores First-in, First-out (FIFO) scheduling behavior by wrapping JS native methods.

73. Min Stack
    - Pattern: Stack with Min tracking
    - Why: Keeps track of the minimum element in the stack in O(1) time using an auxiliary tracking stack.

74. Implement Stack using Queues
    - Pattern: Queue element rotation
    - Why: Simulates LIFO stacks using FIFO queues by shuffling elements inside helper buffers.

[MEDIUM LEVEL]

75. Implement Queue using Stacks
    - Pattern: Two Stacks conversion
    - Why: Focuses on managing and reversing element orders between LIFO structures to behave as FIFO.

76. Next Greater Element
    - Pattern: Monotonic Stack
    - Why: Uses a stack to remember indices/elements needing a future larger value, scanning in O(N).

77. Task Scheduler / Job Queue
    - Pattern: Queue FIFO scheduling
    - Why: Simulates asynchronous task processing (like BullMQ, email dispatching queues, or task pools).

78. Simplify Path
    - Pattern: Unix-like path parsing via Stack
    - Why: Extremely relevant for backend Node.js path resolutions, cleaning redundant directories/backtracks.

79. Sliding Window Maximum
    - Pattern: Deque / Monotonic Queue
    - Why: Optimally tracks sliding window constraint maximums by maintaining indices in a double-ended queue.

80. Check Balanced Parentheses (Multi-Type)
    - Pattern: Stack parsing
    - Why: Extends basic brackets verification by checking all brace forms matching pairs.

TOPIC 5: RECURSION & BACKTRACKING (10 Questions)
================================================================================

[EASY LEVEL]

81. Print 1 to N and N to 1 Recursively
    - Pattern: Recursive head/tail traversals
    - Why: Introduces basic call sequences and trace stack frames.

82. Sum of Digits Recursively
    - Pattern: Modulo + division recursion
    - Why: Accumulates remainder digits down recursive call stack.

83. Calculate Factorial & Fibonacci Recursively
    - Pattern: Recursive numeric reductions
    - Why: Builds basic single and double branched recursion calls.

84. Power Function (X^N) Recursively
    - Pattern: Binary division recursion (X^(N/2))
    - Why: Computes power recursively in O(log N) operations.

[MEDIUM LEVEL]

85. Flatten a Nested Array Recursively
    - Pattern: Recursive flat scanning
    - Why: Resolves deeply nested array structures, mimicking operations commonly done on nested state trees.

86. Flatten a Nested Object Recursively
    - Pattern: Recursive object keys resolution
    - Why: flattens nested state variables into simple key maps.

87. Deep Clone an Object Recursively
    - Pattern: Recursive reference deep cloning
    - Why: Clones nested objects by values to protect React immutable state structures.

88. Search in Nested JSON/Folder Structure
    - Pattern: Recursive DFS traversal
    - Why: Models navigation in nested databases or recursive sidebar UI components.

89. Generate Parentheses Combinations
    - Pattern: Backtracking bracket counts check
    - Why: Explores balanced bracket combinations recursively.

90. Subsets / Power Set Generation
    - Pattern: Backtracking pick / skip recursion
    - Why: Computes all possible subsets of lists.

TOPIC 6: TREES & BST (10 Questions)
================================================================================

[EASY LEVEL]

91. Tree Node Definition & Traversals (DFS)
    - Pattern: Recursive Inorder/Preorder/Postorder DFS
    - Why: Foundation for tree traversal patterns needed to parse, diff, or update HTML DOM trees.

92. Height / Maximum Depth of a Tree
    - Pattern: DFS recursion (1 + max(left, right))
    - Why: Finds maximum nesting depth of HTML elements in DOM branches.

93. Count Leaf Nodes
    - Pattern: DFS leaf check recursion
    - Why: Counts endpoint nodes without children.

94. Search in a Binary Search Tree (BST)
    - Pattern: BST node val lookup
    - Why: Fast O(log N) data tree search applications.

95. Path Sum Check
    - Pattern: DFS target subtract scan
    - Why: Validates if any root-to-leaf path sums to target.

[MEDIUM LEVEL]

96. Level Order Traversal (BFS)
    - Pattern: Queue FIFO level scan
    - Why: Traverses horizontal layers, useful for parsing layouts in segments.

97. Find Node in Matching DOM Trees
    - Pattern: Tree mapping DFS scans
    - Why: Standard frontend challenge finding matching nodes in copied HTML structures.

98. Collect Class Names in DOM Tree
    - Pattern: DFS recursive match
    - Why: Simulates browser search selectors like querySelectorAll.

99. Validate Binary Search Tree
    - Pattern: Recursion bounds limits checks
    - Why: Enforces range requirements on tree nodes in O(N).

100. Lowest Common Ancestor (LCA) in Tree/BST
     - Pattern: DFS recursion / BST splits
     - Why: Locates common parents in nested systems or directory structures.

TOPIC 7: LINKED LISTS (8 Questions)
================================================================================

[EASY LEVEL]

101. Reverse a Linked List
     - Pattern: Iterative / Three Pointers
     - Why: Essential practice for manipulating node reference links (next pointers) dynamically.

102. Detect Loop in a Linked List
     - Pattern: Floyd's Cycle / Fast-Slow Pointers
     - Why: Fast pointer catches slow pointer in O(N) time if a cycle reference exists.

103. Find Middle of a Linked List
     - Pattern: Fast & Slow Pointers
     - Why: Solves single-pass midpoints by stepping fast pointer twice as fast as slow pointer.

104. Delete Node in a Linked List
     - Pattern: Value substitution + skip node
     - Why: Deletes node in O(1) when given reference without traversing head.

[MEDIUM LEVEL]

105. Merge Two Sorted Linked Lists
     - Pattern: Two Pointers
     - Why: Chains nodes of two sorted lists in-place in sorting order without allocation.

106. Remove N-th Node From End
     - Pattern: Two Pointers with Delay gap
     - Why: Pushes lead pointer N steps ahead, then moves both to find deletion targets in a single scan.

107. Add Two Numbers represented as Linked Lists
     - Pattern: Math carry scan
     - Why: Mimics arithmetic additions on reference arrays, tracking carry overflows.

108. Intersection of Two Linked Lists
     - Pattern: Difference in lengths offset / Two Pointers swap
     - Why: Aligns list lengths to find meeting reference nodes in O(N) time.
