================================================================================
PROCODRR 21-DAY SYLLABUS - DSA PREPARATION ROADMAP FOR MERN DEVELOPERS
================================================================================

This roadmap is built exactly around the ProCodrr 21 Days of Problem Solving course.
It contains 150 questions (30 per topic: 15 Easy, 15 Medium) covering basic logic, 
digits, strings, arrays, sorting, searching, recursion, trees, and BSTs.

Each question contains:
- Required Algorithm/Pattern
- Reasoning (Why) explaining its importance for MERN stack developers.

================================================================================
TOPIC 1: NUMBERS, MATH, LOGIC & STAR PATTERNS (30 Questions)
================================================================================

[EASY LEVEL]

1. Count Digits in a Number
   - Pattern: Arithmetic division / modulo loop
   - Why: Foundational loop logic for parsing digit lengths without string methods.

2. Sum of Digits of a Number
   - Pattern: Arithmetic decomposition
   - Why: Basic accumulation operations showing arithmetic parsing.

3. Reverse a Number
   - Pattern: Mathematical rebuilding (num * 10 + remainder)
   - Why: Essential numeric manipulation logic without allocating memory for string casts.

4. Check Palindrome Number
   - Pattern: Compare original with reversed number
   - Why: Classic arithmetic validation of symmetry.

5. Check Armstrong Number
   - Pattern: Digit powers accumulation
   - Why: Tests loop-based accumulation and power arithmetic logic.

6. Find HCF / GCD of Two Numbers
   - Pattern: Euclidean algorithm (subtraction/modulo)
   - Why: Standard recursion/iteration logic for finding largest common divisor.

7. Find LCM of Two Numbers
   - Pattern: GCD relation formula: (A * B) / GCD(A, B)
   - Why: Tests mathematical optimizations utilizing precomputed GCDs.

8. Check if a Number is Prime
   - Pattern: Square root boundary scan (loop up to sqrt(N))
   - Why: Demonstrates boundary limit optimization (O(sqrt(N)) instead of O(N)).

9. Print Fibonacci Series up to N Terms
   - Pattern: Iterative state swaps (prev, curr = curr, prev + curr)
   - Why: Basic progression logic displaying sequential swaps.

10. Check if a Number is Odd/Even without Modulo (%)
    - Pattern: Bitwise AND (& 1)
    - Why: Demonstrates bitwise logic which is faster than division/modulo operators.

11. Swap Two Numbers Without a Third Variable
    - Pattern: Arithmetic additions/subtractions or XOR
    - Why: Exercises variable value swaps using math references instead of temp stack variables.

12. Print a Square Star Pattern of Size N
    - Pattern: Nested loops (row & col)
    - Why: Foundation for rendering grids and matrices in text layouts.

13. Print a Right Triangle Star Pattern of Size N
    - Pattern: Nested loops with conditional boundaries
    - Why: Builds basic multi-dimensional index logic.

14. Print an Inverted Right Triangle Star Pattern of Size N
    - Pattern: Nested loops with decreasing index limits
    - Why: Teaches logic where inner iteration counts shrink dynamically.

15. Check if a Year is a Leap Year
    - Pattern: Divisibility check logic (mod 4, 100, 400)
    - Why: Classic check showing structured boolean branch conditions.

[MEDIUM LEVEL]

16. Prime Factorization of a Number
    - Pattern: Trial division division loops
    - Why: Shows dynamic loop boundary reduction by dividing out found factors.

17. Find N-th Fibonacci Number
    - Pattern: Iterative space-optimized accumulation
    - Why: Reaches O(N) time and O(1) space instead of recursive exponential complexity.

18. Find All Prime Numbers up to N
    - Pattern: Sieve of Eratosthenes
    - Why: Legendary algorithm showing composite number marking, saving redundant loops.

19. Print a Pyramid Star Pattern of Size N
    - Pattern: Multi-loop row indentation (spaces + stars)
    - Why: Integrates complex row formatting logic with mathematical spacing.

20. Print a Diamond Star Pattern of Size N
    - Pattern: Symmetric pattern reflection (increasing then decreasing stars)
    - Why: Advanced nested-loop logic handling pattern reversals mid-execution.

21. Find HCF / GCD of an Array of Numbers
    - Pattern: Cumulative GCD scan
    - Why: Extends binary GCD functions across list elements using array reductions.

22. Find LCM of an Array of Numbers
    - Pattern: Cumulative LCM scan
    - Why: Extends binary LCM functions across list elements using array reductions.

23. Convert Decimal Number to Binary Representation
    - Pattern: Division by 2 stack builder / bitwise shifts
    - Why: Base-10 to base-2 numeric conversion logic.

24. Convert Binary Number to Decimal Representation
    - Pattern: Base-2 exponent sum scan
    - Why: Parsers binaries to return numeric values.

25. Check if a Number is a Perfect Number
    - Pattern: Divisors summation loop up to N/2
    - Why: Verifies if proper divisors sum up to the original value.

26. Find All Factors of a Number
    - Pattern: Loop scan up to sqrt(N) in pairs
    - Why: Optimizes factor collection in O(sqrt(N)) time.

27. Print a Hollow Square Star Pattern of Size N
    - Pattern: Nested loops with boundary checks (row == 0 || col == 0, etc.)
    - Why: Introduces logical OR conditions within grid render loops.

28. Check if a Number is a Happy Number
    - Pattern: Digit square sum with Floyd's cycle detection
    - Why: Tracks cyclic repetitions in digit operations using loop sets.

29. Check if a Number is a Harshad Number
    - Pattern: Sum of digits divisibility check
    - Why: Divides numbers by their cumulative digit sums to verify integer status.

30. Print Prime Factors of a Number in Sorted Order
    - Pattern: Factor collection + sorted array insertion
    - Why: Combines prime factoring loops with data array collation.

TOPIC 2: STRINGS & SEARCHING (30 Questions)
================================================================================

[EASY LEVEL]

31. Reverse String
    - Pattern: Two Pointers / In-place swap
    - Why: Reversing characters from both ends inward requires O(1) extra space and reverses the string in-place.
    - File: DSA/strings/01-reverseString.js

32. Check Palindrome
    - Pattern: Two Pointers
    - Why: Moving pointers inward from both ends allows early exit as soon as a mismatch is found.
    - File: DSA/strings/02-checkPalindrome.js

33. Count Vowels
    - Pattern: Iteration / Character Set Matching
    - Why: Scanning the string against a set of vowels identifies occurrences in O(N) time.
    - File: DSA/strings/03-countVowels.js

34. Count Consonants
    - Pattern: Iteration / Filter
    - Why: Filters out vowels and special characters, scanning only alphabetic consonants in O(N) time.
    - File: DSA/strings/04-countConsonants.js

35. Character Frequency
    - Pattern: Hash Map / Frequency Array
    - Why: A Hash Map provides O(1) lookup and insertions, ideal for tracking character occurrences.
    - File: DSA/strings/05-charFrequency.js

36. Remove Duplicate Characters from String
    - Pattern: Hash Set / Filter
    - Why: A Set inherently holds unique values, filtering out duplicate entries in O(N) time.

37. Capitalize First Letter of Each Word
    - Pattern: String manipulation / Word Boundary scanning
    - Why: Iterating and uppercase-matching characters after space boundaries cleans input.

38. String Rotation Check
    - Pattern: Concatenation ((A + A).includes(B))
    - Why: If string B is a rotation of A, it must be a substring of A concatenated with itself.

39. First Repeating Character in a String
    - Pattern: Hash Set
    - Why: Checking elements while iterating allows immediate detection of the first duplicate.

40. First Non-Repeating Character in a String
    - Pattern: Hash Map (Two-pass tracking)
    - Why: First pass builds counts; second pass retrieves the first character with a frequency count of 1.

41. Remove All Spaces from a String
    - Pattern: Iteration filter / RegExp replace
    - Why: Cleans and matches characters by stripping whitespaces.

42. Check if String Contains Only Digits
    - Pattern: Char-code boundary scan / RegExp test
    - Why: Validates numerical inputs on forms/text fields.

43. Linear Search: Find Index of Character in String
    - Pattern: Linear Scan
    - Why: Iterates index by index to locate target, exiting early on first match.

44. Count Occurrences of a Specific Character
    - Pattern: Linear accumulation scan
    - Why: Traverses character indices, counting specific character matches.

45. FizzBuzz String Compilation
    - Pattern: Conditional iteration loop
    - Why: Compiles numeric matches to specific text strings for output sequences.

[MEDIUM LEVEL]

46. Longest Substring Without Repeating Characters
    - Pattern: Sliding Window (Set/Map)
    - Why: Dynamically slides the window to expand for valid substrings and shrinks from the left on duplicates.

47. Longest Palindromic Substring
    - Pattern: Expand Around Center
    - Why: Expanding outwards from 2N-1 potential centers checks palindromic bounds in O(N^2) time.

48. Valid Parentheses
    - Pattern: Stack
    - Why: Last-in, first-out (LIFO) order matches nested brackets (closing bracket must match last open bracket).

49. String Compression
    - Pattern: Two Pointers (Read & Write)
    - Why: In-place editing requires a read pointer to count matches and a write pointer to output the summary.

50. Group Anagrams
    - Pattern: Hash Map with Sorted String Keys
    - Why: Sorted representations of anagrams are identical, serving as grouping keys in a map.

51. Roman to Integer
    - Pattern: Left-to-Right scanning with Lookahead
    - Why: Sequential addition with lookahead handles subtractions (like IV = 5 - 1).

52. Integer to Roman
    - Pattern: Greedy subtraction with value map
    - Why: Maps Roman numbers in descending order, building strings by subtractive compilation.

53. Longest Common Prefix
    - Pattern: Vertical character scanning
    - Why: Compares indices across all elements, failing immediately upon first mismatch.

54. Valid Anagram
    - Pattern: Frequency Map comparison
    - Why: Anagrams must share identical character frequencies, matching count tables in linear time.

55. Binary Search on Sorted Array of Characters
    - Pattern: Two-pointer divide and conquer (Low, High, Mid)
    - Why: Excludes half the elements each step to search characters in O(log N) complexity.

56. Find All Occurrence Indices of Pattern in String
    - Pattern: Sliding window match / Substring scan
    - Why: Slides matching bounds to collect start indices of custom substrings.

57. Reverse Words in a String
    - Pattern: Split & Reverse / Two Pointers
    - Why: Reversing word positions while cleaning spaces maintains linear complexity.

58. Isomorphic Strings
    - Pattern: Double Hash Mapping
    - Why: Maps characters in string A to B and vice versa, verifying a strict 1-to-1 character relation.

59. Validate IP Address
    - Pattern: Split blocks + numeric check / Regex
    - Why: Verifies proper syntax of network strings for APIs/databases.

60. String to Integer (atoi)
    - Pattern: Sign matching + numeric digit accumulator
    - Why: Implements parser logics for parsing numeric values from leading string data.

TOPIC 3: ARRAYS & SORTING (30 Questions)
================================================================================

[EASY LEVEL]

61. Reverse Array
    - Pattern: Two Pointers
    - Why: Swapping elements from ends inward reverses the array in-place in O(N) time.

62. Find Maximum & Minimum Element
    - Pattern: Linear Scan
    - Why: Iterating once while maintaining minimum and maximum bounds is optimal.

63. Second Largest Element
    - Pattern: Single Pass Tracking
    - Why: Keeps track of current largest and second largest values in O(N) time, avoiding O(N log N) sort.

64. Check if Array is Sorted
    - Pattern: Single Pass comparison
    - Why: Compares current element to next element to check non-decreasing order in O(N) time.

65. Remove Duplicates from Sorted Array
    - Pattern: Two Pointers (Read & Write)
    - Why: Since elements are sorted, duplicate values are adjacent and can be skipped.

66. Move Zeroes
    - Pattern: Two Pointers (Write Pointer)
    - Why: Write pointer shifts non-zero items leftwards in order, then fills trailing spots with zero.

67. Contains Duplicate
    - Pattern: Hash Set
    - Why: Instant O(1) set lookup reveals duplicates.

68. Intersection of Two Arrays
    - Pattern: Hash Set
    - Why: Hash Set lookups match items in O(N) time rather than nested checks in O(N^2).

69. Bubble Sort
    - Pattern: Swap adjacent elements in nested loops
    - Why: Foundational conceptual sorting showing loop execution. Time: O(N^2), Space: O(1).

70. Selection Sort
    - Pattern: Find minimum element and place at boundary
    - Why: Simple algorithm minimizing index swaps. Time: O(N^2), Space: O(1).

71. Insertion Sort
    - Pattern: Build sorted array incrementally
    - Why: Highly efficient for nearly sorted data arrays. Time: O(N^2), Space: O(1).

72. Linear Search on Array
    - Pattern: Index traversal scan
    - Why: Compares list elements sequentially to find index target.

73. Binary Search on Sorted Array
    - Pattern: Divide and conquer index divisions
    - Why: Halves searching array boundaries dynamically to search elements in O(log N) time.

74. Merge Two Sorted Arrays
    - Pattern: Two Pointers
    - Why: Compares the smallest available items of both arrays to build a merged sorted list.

75. Count Occurrences of a Number in Array
    - Pattern: Linear scan counter / Binary search boundaries
    - Why: Tallies occurrences of numbers in linear or log time.

[MEDIUM LEVEL]

76. Two Sum
    - Pattern: Hash Map
    - Why: Storing visited numbers allows finding the target complement (target - current) in O(1) time.

77. Three Sum
    - Pattern: Sorting + Two Pointers
    - Why: Sorting groups values to avoid duplicates easily and lets two pointers seek outer bounds.

78. Maximum Subarray (Kadane's Algorithm)
    - Pattern: Dynamic Programming / Greedy
    - Why: Decides at each index whether to add value to running sum or start a new subarray.

79. Merge Intervals
    - Pattern: Sorting
    - Why: Sorting intervals by start times ensures overlapping segments are contiguous.

80. Rotate Array
    - Pattern: Reversal Trick / Auxiliary Space
    - Why: Reversing parts of the array in place handles shift rotations in O(N) time and O(1) space.

81. Sort Colors (Dutch National Flag)
    - Pattern: Three Pointers (Low, Mid, High)
    - Why: Low and High pointers act as placement anchors for 0s and 2s, sorting in a single pass.

82. Product of Array Except Self
    - Pattern: Prefix & Suffix Products
    - Why: Storing cumulative products left and right of an element computes total products in O(N) without division.

83. Majority Element
    - Pattern: Boyer-Moore Voting Algorithm
    - Why: Pairs of differing values are cancelled out, leaving the majority element in O(1) space.

84. Container With Most Water
    - Pattern: Two Pointers
    - Why: Moves inward from ends, updating pointers that point to smaller heights.

85. Subarray Sum Equals K
    - Pattern: Prefix Sum + Hash Map
    - Why: Counts target sum matches by searching prefix sum differences (prefix - k) in a map.

86. Maximum Product Subarray
    - Pattern: Dynamic Programming (Min-Max Tracking)
    - Why: Stores maximum and minimum values because negative multiplications flip minimums to maximums.

87. Find All Duplicates in Array
    - Pattern: In-Place Marking (Index Sign Swap)
    - Why: Negating values at corresponding indices marks them as visited using the original array space.

88. Search in Rotated Sorted Array
    - Pattern: Modified binary search pivot check
    - Why: Determines which half of the rotated array is sorted to target searches in O(log N).

89. Find Peak Element in Array
    - Pattern: Binary search binary halves comparison
    - Why: Navigates values looking for boundary peaks in O(log N) time.

90. Sort Array of Objects (Custom Comparator)
    - Pattern: Array.prototype.sort() with comparison function ((a, b) => a.prop - b.prop)
    - Why: Basic MERN application. You receive an array of objects from the database/API and must sort it by date, name, or price dynamically before rendering.

137. Find Node in Duplicate DOM Trees

138. Collect Class Names in a DOM Tree
     - Pattern: DFS recursive match

139. Validate if Binary Tree is valid BST
     - Pattern: Recursion bounds limits checks

140. Lowest Common Ancestor (LCA) in BST

142. Delete Node in a BST

     - Why: Safely handles element drops in sorted trees.

143. Convert Sorted Array to Balanced BST
     - Pattern: Recursive mid element split inserts
     - Why: Transforms arrays into fast balanced lookups trees.

144. Right Side View of Binary Tree
