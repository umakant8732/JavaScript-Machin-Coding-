PHASE 1: MEMORY & TYPES (Pehle yeh — baaki ka base)
================================================================================

1. Call Stack vs Heap (Short Diagram)
   - Call Stack: function calls / execution order (LIFO). Sync code yahan chalta hai.
   - Heap: objects/arrays/functions ka actual data store (badi memory area).
   - Primitive values mostly stack-side copy; objects heap pe, variable sirf reference rakhta hai.

   Diagram (yaad rakhna):
   ```
   CALL STACK (execution)          HEAP (data)
   ┌─────────────────┐             ┌──────────────────────┐
   │ fnB()           │             │  { name: "Umakant" } │
   │ fnA()           │  reference  │  [1, 2, 3]           │
   │ main/script     │ ──────────► │  large objects live  │
   └─────────────────┘             └──────────────────────┘
   Stack = "ab kaunsa function chal raha"
   Heap  = "data kahan pada hai"
   ```

2. Value vs Reference Types
   - Primitives (number, string, boolean, null, undefined, symbol, bigint) → copy by value
   - Objects / arrays / functions → copy by reference (same heap object)
   - Why `obj2 = obj1` dono change karta hai; kaise alag reference banaye

3. == vs === and Truthy / Falsy
   - === strict (type + value); == loose (coercion) — prefer ===
   - Falsy: 0, "", null, undefined, NaN, false
   - ?? (nullish) vs || (falsy) — short difference

4. null vs undefined
   - undefined = missing / not assigned
   - null = intentional empty
   - Optional chaining ?.

PHASE 3: OBJECTS, COLLECTIONS & COPY
================================================================================

9. Prototype Chain (Basics Only)
   - Objects inherit via [[Prototype]]
   - Array methods live on Array.prototype
   - Enough: "arr.map works because of prototype"
   - Skip deep custom inheritance for now

10. Object as HashMap + Map + Set + WeakMap + WeakSet
    - HashMap idea: key → value fast lookup O(1) avg
    - Plain Object `{}`: string/symbol keys; good for simple maps (freq count)
    - Map: any type keys, .get/.set/.has, size, better for frequent add/delete
    - Set: unique values only; .add/.has — duplicates / visited tracking
    - WeakMap: keys must be objects; weak refs → GC friendly; not iterable
    - WeakSet: weak object membership only
    - Junior rule of thumb:
        freq / Two Sum style     → Object or Map
        unique / seen            → Set
        private metadata on DOM/obj → WeakMap (awareness)
    - Note: Deep WeakMap GC theory skip; bas difference + kab use

11. Shallow vs Deep Copy
    - Spread / Object.assign = shallow (nested still shared)
    - Deep: structuredClone / recursive clone idea
    - When shallow is enough in apps

PHASE 5: ASYNC JS (Promises → await → Event Loop)
================================================================================

13. Promises (States, Chaining, all vs allSettled)
    - States: pending → fulfilled / rejected
    - .then / .catch / .finally; microtasks
    - Promise.all: saari success chahiye; EK bhi reject → overall reject
    - Promise.allSettled: saari settle hone do; har result {status, value/reason}
    - One-liner: all = fail-fast | allSettled = wait for everyone, no fail-fast

14. Async / Await
    - Syntactic sugar over Promises
    - try/catch
    - Sequential await vs parallel (Promise.all)

15. Event Loop & Execution Context
    - Call stack + Web APIs + macrotask queue (setTimeout) + microtask queue (Promises)
    - Order: sync → microtasks → macrotasks
    - Why UI doesn't freeze on async work
    - Ties back to Q1 stack diagram

PHASE 6: DOM & BROWSER (MERN frontend rounds)
================================================================================

16. DOM Tree & Selecting / Creating Nodes
    - querySelector / querySelectorAll vs getElementById
    - createElement, appendChild, textContent vs innerHTML (XSS)
    - classList add/remove/toggle

17. Events: addEventListener + preventDefault vs stopPropagation
    - click, input, submit, keydown
    - event.target vs event.currentTarget
    - preventDefault(): browser ka DEFAULT action roko
        Scenario A: form submit → page reload mat ho
        Scenario B: <a href> click → navigate mat ho
        Scenario C: input type=number scroll / context menu (jab default unwanted ho)
    - stopPropagation(): event ko parent listeners tak mat jane do (bubble/capture stop)
        Scenario A: button inside clickable card — button click pe card ka click na chale
        Scenario B: dropdown item click — document pe laga "outside click close" na fire ho galat time pe
        Scenario C: nested menus — child click parent handler ko na trigger kare
    - Dono saath: form button pe kabhi preventDefault + stopPropagation (rare; samajh ke use)
    - Rule: default browser behavior → preventDefault | parent handlers block → stopPropagation

18. Event Bubbling, Capturing & Delegation
    - Capture → target → bubble
    - Delegation: one parent listener for many children (dynamic lists)
    - Real use: todo delete buttons, table rows

19. Debounce vs Throttle (Concept Only)
    - Debounce: wait until quiet (search)
    - Throttle: at most once per interval (scroll/resize)
    - Code → Machine Coding file

20. Browser Storage
    - localStorage vs sessionStorage vs cookies
    - JSON.stringify / parse
    - Sync API / size limits (awareness)

21. Rendering Basics (Junior-friendly)
